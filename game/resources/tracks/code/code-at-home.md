# Helping with Code

## If you have never programmed

Good news: that is not a disadvantage here. The most useful thing you can
offer is not knowledge, it is a willingness to be told how something works
by a twelve-year-old. Explaining is where the understanding gets built, and
you cannot fake being confused convincingly, so genuine questions are the
best tool you have.

## What a loop is, in one paragraph

A loop repeats instructions. Every loop needs three things: where to start,
when to stop, and how to move from one step to the next. Miss any one and
the loop either never starts, never stops, or never gets anywhere. If your
child's program hangs forever, ask which of those three is missing — it is
almost always the "when to stop."

## What a variable is, in one paragraph

A named box holding a value that can change. `count = 0` puts zero in a box
called count. This maps directly onto the algebra they are doing in maths,
and pointing that out is worth doing — students often do not notice that
`x` in maths class and `x` in code are the same idea.

## The most useful thing you can say

> "What did you expect it to do, and what did it actually do?"

Almost every bug lives in the gap between those two sentences. Getting a
child to say both out loud, precisely, finds a startling number of problems
without you knowing anything about the code.

## What not to do

**Do not type on their keyboard.** Even to fix something small. Once you
take the keyboard, the session becomes yours and their learning stops. Point
at the screen instead, and only after they have asked.

**Do not correct spelling errors immediately.** Finding a typo is a skill.
A computer being unforgivingly literal is a real lesson about computers.

## Where this goes

The habits in this track — break the problem down, test what you assumed,
read the error rather than panicking at it — matter far more than the
syntax. Syntax gets forgotten and re-learned. The habits do not.
