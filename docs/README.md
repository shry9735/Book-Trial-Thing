## Generated documentation

Two kinds, built by `./scripts/gendocs.sh`.

### API reference — `docs/api/`

Every module, function and signature, rendered from the docstrings already
in the source by [pdoc](https://pdoc.dev).

```bash
./scripts/gendocs.sh            # build into docs/api/
./scripts/gendocs.sh --serve    # live-reloading server on :8080
open docs/api/index.html
```

**Not committed.** Generated HTML makes diffs unreadable and it is 3 MB.
Build it locally, or let `.github/workflows/docs.yml` publish it to GitHub
Pages on every push to `main`.

The docstrings *are* the documentation, so the reference is only as good
as they are. When you change a function's behaviour, change its docstring
in the same commit.

### Call graph — [`docs/CALLGRAPH.md`](CALLGRAPH.md)

```bash
python scripts/callgraph.py                  # regenerate
python scripts/callgraph.py --check          # CI: fail on layering breaks
python scripts/callgraph.py --route /api/quiz   # what does this handler touch?
```

Committed, unlike the API reference, because it is Markdown: GitHub renders
its Mermaid diagrams inline and its diff is reviewable. A pull request that
changes the module graph shows you that it did.

That last invocation is the useful one day to day:

```
  POST /api/quiz
    handler  app.api_quiz  (line 1119)
    guards   signed in
    does     Check one answer and record the attempt.
    calls
      billing.entitlement_for
      billing.lesson_is_free
      db.record_answer
      db.user_by_id
```

## Why not Doxygen

Doxygen is built around C++ and treats Python as an afterthought — it
parses it without type information, and its call graphs need Graphviz to
render into images that cannot be reviewed in a pull request or read on a
phone.

pdoc reads the docstrings this codebase already has, needs no
configuration file, and produces a searchable site. The call graph is
generated by `scripts/callgraph.py`, which walks the AST directly and
emits Mermaid — so it lives in the repository as text, renders on GitHub
without any tooling, and can additionally *enforce* the layering rather
than just draw it.

That last part is the real gain over any off-the-shelf tool:
`callgraph.py --check` fails the build if `db.py` starts importing
`app.py`. A picture would only have shown it.
